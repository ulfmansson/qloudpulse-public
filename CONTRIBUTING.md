# Contributing

## We do not take pull requests

Only the qloudpulse maintainers change the code in this repository. A pull request from anyone else is closed
automatically, with a comment pointing back here. There are no exceptions.

## We do want your bug reports and feature requests

Tell us what is broken or what you need, and we will fix or build it at our discretion and maintain it from then on.

| You want to | Go to |
|---|---|
| Report a bug in the agent, the chart or a CLI | [Open an issue here](https://github.com/ulfmansson/qloudpulse-public/issues/new/choose) |
| Ask for a feature | In qloudpulse, **Suggest a feature** ([app.qloudpulse.com/account/requests](https://app.qloudpulse.com/account/requests)), or [open an issue here](https://github.com/ulfmansson/qloudpulse-public/issues/new/choose) if you are not a customer yet |
| See what others have asked for, and star it | [qloudpulse.com/requests.html](https://qloudpulse.com/requests.html) |
| Report a problem with the qloudpulse service itself | In qloudpulse, **Report a problem** |
| Report a security vulnerability | Mail **support@qloudpulse.com** with "Security" in the subject. Not an issue: issues are public |

A good report says what you ran, what you expected, and what happened instead, with the version and the relevant log
lines. Leave out tokens, account ids and anything else you would not post publicly.

If an issue includes code, such as a patch or a snippet showing the fix you have in mind, you license it to us under
the [Apache License 2.0](LICENSE), as the rest of this repository is. We may use it, or write our own.

## Why

AI agents now write working code faster than a person can review it, and a large change looks the same whether a person
or an agent wrote it. This repository is what customers install into their clusters and run in their CI, so we keep the
supply chain short: every change is written by people and agents under our direct control, from a request we have read
and checked, including for prompt injection and malicious intent.

A clear report is worth more to us than a patch, because it tells us what you need rather than one way to get there.

## Credit

If we fix your issue, we are happy to name you as a co-author on the pull request that does it. Say so in the issue.
